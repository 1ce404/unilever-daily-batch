# QC（第 ⑤⑦⑧⑨ 步）

QC 标准原文：https://tezign.feishu.cn/docx/HrWtd4mowoGeAUxtYeFc91KhnJb（每天 `fetch_sources.py` 拉到 `sources/qc.txt`）。分四层，越往前越便宜：

| 层 | 什么时候 | 谁做 | 拦什么 |
|---|---|---|---|
| 1 脚本 lint | 写完脚本、审核人改完之后 | `lint_copy.py` | 禁用词、极限词、时间承诺、机制数字（及多久没核对）、串系列卖点、产品名缺失 / 被拆开 / 太早出现 / 卖点句没带、CTA、字幕放不下的长句、素材接不住的场景词、女生视角词、**照抄**（跟范本 / 近 7 天 / 当天其它稿太像）。**不查文风** |
| 2 人审脚本 | 每天每个 brief | 审核人 | 口吻对不对、卖点讲没讲清、「和旧稿比」相似度偏高的、lint 的提醒项 |
| 3 平台 AI 审核 | 每条成片渲染完 | Clipo `video-cuts/review` | 成片层面：画面与口播一致、产品外观一致、画面质量、字幕、音画同步 |
| 4 人工抽查 | 报告出来后 | 你 + 审核人 | 只看 AI 驳回的，和每个 brief 抽 1 条通过的 |

## 层 1：QC 文档 → config 的对应

| QC 文档条目 | 配置 / 检查 |
|---|---|
| 广告法 1 绝对化用语 | `banned_words.error`（首选、唯一、顶级…）+ `regex_error`（最…、第一…，放过「最近 / 第一次」） |
| 广告法 2 功效夸大 | `banned_words.error`（根治、治疗、防脱、生发）；其余靠人审 |
| 广告法 4 时间承诺 | `regex_error` 数字 + 小时/天/周；`regex_warn` 中文数字；`warn`「长效」「持久」 |
| 广告法 5 权威背书 | `warn`「临床」「专家」「医生」：只有资料里有出处才能写 |
| 广告法 6/7 竞品、价格 | `error` 全网、领先、最低价、历史最低、原价、性价比 |
| 产品类 1/3 信息与机制准确 | 产品全名必须完整出现；机制数字只能是 `mechanism.allowed_numbers` |
| 产品类 5 系列不可混淆 | `foreign_claims`：别的 SKU 的卖点出现即报错 |
| 平台通用 1 文字规范 | 短句按显示宽度 > 12 提醒、> 20 报错，产品名不跨句，不带 emoji / `[#…]`；「齁」字会被判错别字，不写 |
| 清扬定制 | CTA「戳直播间」；`banned_words` 里的近期卡审词 |
| AIGC 标准 | 靠人审 + 平台审：不要掉头屑 AI 素材、明星脸、AI 仿真人第一人称使用；AI 真人不要秃顶 / 头顶稀疏（用户 11-11） |

QC 文档或近期脚本 callout 新增了条目，**先改 config 再写脚本**。新的品牌定制段（如「Dove-PC：不能写提亮，要写焕亮」）进对应品牌的 config。

## 层 3：平台 AI 审核

`clipo_batch.py poll` 在渲染完成后自动提交审核，结论写回 `state.json`：`ai_review` = `pass` / `reject`，`ai_reason` 是原因（会引用 QC 条款号，如「违反广告法类第4条」）。

平台审核用的是**产品级提示词** `video_cut_review`（`GET /products/{id}/prompts`），和建脚本、改写的提示词一样归平台管。要加清扬定制段和近期卡审词，告诉用户在平台改；用户明确让我改时才用：

```bash
# 把 QC 通用 + 清扬定制 + 近期卡审点写进产品的审核提示词
curl -s -X PUT "$BASE/api/v1/products/<product_id>/prompts/video_cut_review" \
  -H 'Content-Type: application/json' --data-binary @review_prompt.json   # {"prompt": "..."}
```

平台审核还读产品 `description`。描述里的机制过时（呼吸瓶还写着「男控油1300g」）会让审核把正确的新机制判成「机制信息不准确」：体检报告里有 ⚠️ 时提醒用户更新描述。

## 层 4：人工抽查

报告出来后：

- `report` 已把需处理的条目按原因分好类（改写违规 / 文案 / 画面素材 / 产品信息过时 / 其他），每类附处理办法。分类是按原因关键词猜的：「其他」和你觉得分错的看驳回原因文字，不用打开视频
- 每个 brief **最多**抽 1 条通过的，看封面和前 3 秒：开头有没有抓人、产品外观是不是本品（不是别的系列）、字幕有没有压住产品。不逐条看、不每条抽帧（用户 11-13：逐条看图让返工等了几个小时）；用户说「不用检查」就不抽，直接交付
- 平台 AI 审核偶有误判（11.04：把双重酰胺判成「虚构成分」、把排期指定的 SCA 判成「无依据」）。看到这类原因告诉用户，由用户决定放行，不自己改结论
- 「改写违规」（`copy_issues` 非空：Clipo 改写后出现禁用词、丢了产品名或卖点）的条目一律当驳回处理，并把新出现的违规词补进 `banned_words`

不要说「全部通过」除非报告里 `reject` 和未完成都是 0。
